## Scope shipped in this build

1. **Supabase chat schema + RLS** (`supabase/migrations/20260702190000_connect_group_chat.sql`, additive only):
   - `chat_room_creators` — server-enforced creator allowlist. No client write path (no policies, no grants); seeding is a Dawson-approved operator action. Initial creators intended: Dawson and Lisa.
   - `chat_rooms` — class/show/community rooms; invite code is server-generated by trigger (clients cannot pick codes); owner can rename/archive; no client delete.
   - `chat_room_members` — membership with owner/member roles; creator auto-enrolled as owner by trigger; members can self-leave, owners cannot orphan their room; roster visible to members only.
   - `chat_messages` — text-only, append-only (no update/delete policies or grants); insert requires membership AND `sender_id = auth.uid()` (anti-spoof); `sender_name` is stamped server-side from the sender's own profile, with email-local-part display names blanked (0.1.1 PDF lesson) so emails never leak into threads.
   - `is_chat_room_member()` SECURITY DEFINER helper (RLS-recursion-safe), `join_chat_room(code)` RPC for invite-code joins; all definer functions use `set search_path = ''` with EXECUTE revoked from public/anon (and from authenticated for trigger-only functions).
2. **Connect UI**:
   - Connect tab chat card is now an active entry (`Beta` pill) → `/connect/chat`.
   - `ChatRoomsPage` — rooms you belong to, join-by-invite-code, create-room form shown only to allowlisted creators (RLS still enforces server-side). Signed-out testers see the standard tester-access gate.
   - `ChatRoomPage` — WhatsApp-familiar thread: own/incoming bubbles, sender labels (server-stamped name, `Tester` fallback, `You` for self), timestamps, persistent bottom composer (`ion-footer`, safe-area padded), 5s polling while the room is open, empty/error/loading states. Owner sees the room invite code to share with the class.
   - Studios/teachers and events cards remain `Planned`; no invented community content.
3. **Chat store** (`src/stores/chatStore.ts`) following the dailyPracticeStore idiom; text-only send with trim + 4000-char limit mirroring the DB check.

## Dual-brain review pass (same day, pre-approval)

Two read-only reviewer agents ran against the diff before final gates.

RLS/security reviewer — verdict APPROVE-WITH-NITS. All flagged items fixed in the (never-applied) migration before any apply:
1. Owner invite-code overwrite → update grant now column-restricted to `(name, kind, archived_at)` AND the defaults trigger preserves `old.invite_code` on update.
2. Client-forged `created_at` on messages → server-stamped `now()` in the sender trigger.
3. `chat_rooms.created_by` cascade destroying rooms on account deletion → changed to `on delete restrict`; operator archives/deletes rooms first.
4. Full-email display names could pass the local-part filter → stamp now also blocks full-email matches and any name containing `@`.
5. Default-privilege drift → revoke-first from `authenticated` before the explicit grant set.
6. Archived rooms stayed postable → message insert policy now requires `archived_at is null`; `join_chat_room` already refused archived rooms.
Accepted as documented limitations: no rate limit on invite-code RPC (authenticated-only, 40-bit code), invite code readable by members (they already have it), no message edit/delete.
