# Build 0.1.2 — dependency security remediation

Date: 2026-07-02
Branch: `secure-beta-launched`
Build: `0.1.2 / secure-beta-0.1.2`

## Scope

Security/tooling-only dependency remediation after Vercel production install reported npm audit findings on build 0.1.1.

No product features, taxonomy content, Supabase schema, RLS policy, auth flow, or UI copy changes were intentionally made beyond the visible build identifier bump.

## Remediation

Initial `npm audit --json` in `apps/chekhov-toolkit-ionic` reported:

- 16 total vulnerabilities
- 1 critical
- 7 high
- 8 moderate

Affected chains were dev/build/test tooling:

- `vite` / `esbuild` / Vite plugins
- `vitest` / `vite-node`
- `cypress` / `@cypress/request` / `qs` / `uuid`
- `@typescript-eslint/*` / `minimatch`

Changes applied:

- Upgraded Vite build/test stack:
  - `vite` to `^8.1.3`
  - `@vitejs/plugin-vue` to `^6.0.7`
  - `@vitejs/plugin-legacy` to `^8.1.0`
  - `vitest` to `^4.1.9`
- Upgraded Cypress to `^15.18.0`.
- Added targeted npm override:
  - `@typescript-eslint/typescript-estree -> minimatch@9.0.7`
- Bumped app build markers to `0.1.2 / secure-beta-0.1.2` for production-deploy traceability.

## Notes / follow-up

- Vite 8 build emits Lightning CSS warnings for Ionic's upstream `:host-context(...)` CSS utilities. Build still succeeds; this is not app-authored CSS.
- Cypress 15 warns that `allowCypressEnv` is enabled because the gated signed-in persistence spec still uses `Cypress.env()`. This is test-only credential plumbing and should be migrated separately to `cy.env()` / newer Cypress exposure APIs.
- Existing bundle-size warnings remain and should be handled in a later performance/code-splitting pass.
